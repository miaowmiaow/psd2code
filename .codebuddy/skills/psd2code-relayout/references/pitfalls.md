# 实测踩坑清单

以下每条都在真实产物上复现过，按"会让你白干一小时"的程度排序。

## 0e. 跨层合图不要用 CSS 坐标盲合

`prop-icon` 是 4 层叠图（大图 + 圆底 + 内容图），按 CSS 的 `left/top` 算出各层偏移后，用 PIL 合成为一张 120×115 的图替换。

结果：单块测试 `maxΔ=1` 通过，但批量 16 个之后整页差异 **9.4%**，缩略图对比发现南瓜顶部整块变形。

原因有三：

- **层级结构在实例间不一致**：25 个 `prop-icon` 里只有 16 个符合「大图 → prop-bg → rounded → img」的预期，其余结构不同；
- **CSS 尺寸 ≠ 绘制范围**：元素 `width/height` 小于背景图时，浏览器会按元素盒裁切，而 PIL 会把整张图贴上去；
- **坐标是相对的**：`rounded` 相对 `prop-bg`、`prop-bg` 相对 `prop-icon`，累加错一层就整体偏移。

结论：跨层合图必须用**浏览器实测 bbox + 截图裁剪**来合成，不能用 CSS 坐标推算。做不到就宁可不合——模板化（几何同构、不动图像）是零风险的，合图不是。

## 0a. 不要拿原产物的 DOM 结构当依据

PSD 的图层摆放不遵守前端规范，产物里的父子关系和命名都没有语义：

- 同名不同构（`prop-bg-2-2` ~ `prop-bg-2-18` 结构各异）；
- 该对齐的没对齐（截图是 4 列格子墙，产物是 3 列 group + 1 列散落元素）；
- 纯装饰拆三层（`avatar` → `ellipse-2` → `avatar-3`）；
- 坐标无统一参考系（评论卡 `zuixin` 的 `top: -101px` 是旧父级残留）。

结构只能从截图得出。`dom.json` 只用来按 bbox 找素材。

## 0b. 布局重建不能用「零像素差异」验收

`maxΔ ≤ 1` 只适用于「结构不变、只合并图层」。一旦用 flex/grid 重建版面，行高、盒模型、字体渲染都会变，整页零差异是不可能的。

正确做法：按区块 `--region` 分别验收——图片看位置/尺寸误差（≤1px），文本看是否仍在原 bbox 内且内容完整。整页 diff 只作兜底。

用整页零 diff 卡重排，结果一定是"为了 diff 好看而退回绝对定位"，等于白做。

## 0. 副本没改 CSS 引用（最坑）

`cp index_optimized.html index_ai.html` 之后，HTML 里仍写着 `<link href="style_optimized.css">`。
于是：DOM 改了、`style_ai.css` 也改了，但浏览器加载的是**旧样式**。

表现是"改动看起来完全没生效"：实测头像区块整块空白、`maxΔ=255`、`changed=3453`，排查半小时才发现是引用问题。

必须在 Step 0 就把引用改到 `style_ai.css`，改完立刻 `verify_page.py` 跑一次**空改动基线**（此时应当 `max_delta=0`），确认副本本身是干净的。

## 0b. 兄弟层没删：留下无样式空 div

`yue` 与 `shape-3` 是兄弟（同在 `slogan-bg` 下），不是 `shape-3` 的后代。
如果只清理承载层的子树，`yue` 的 DOM 还在，只是 CSS 规则被删了 → 它变成 0 尺寸的 static div。

像素上看不出来（`verify` 会通过），但结构是脏的。删除必须**按 class 精确匹配**：

```python
node = soup.find("div", class_=lambda c: c and cls in c)
node.decompose()
```

## 0c. 纯容器承载层的坐标原点不同

承载层分两种，坐标算法不能混：

- **有背景图的承载层**（如 `shape-3`）：它与其它层同父，`left/top` 一起参与 union；
- **无背景的纯容器**（如 `avatar`，内部才是 `ellipse-2` / `avatar-3`）：子层坐标以**容器为原点**，容器自身的 `left/top` 是它在父容器里的位置，不能参与 union。

混用的后果：`avatar` 算出 82×90 的画布（正确值是 72×72），合成图错位。

## 0d. 嵌套子层不能用 CSS 的 left/top 直接当相对坐标

`avatar-3` 嵌在 `ellipse-2` 内，它的 `left: 4px` 是相对 `ellipse-2`，不是相对 `avatar`。
本次因为 `ellipse-2` 的偏移恰好是 `(0,0)` 才没出错——这是侥幸。

嵌套结构的正确做法：用浏览器实测的 `getBoundingClientRect`（`.relayout/dom.json` 里已有），按**相对画布的绝对坐标**计算偏移。

## 1. 按索引删节点会让后续全错

```python
# ❌ 错误
groups = soup.find_all("div", class_="layer-group")
groups[idx].find(...).decompose()
```

被删的子层本身可能就是 `layer-group`（例如 `prop-bg-18`）。删掉后 `find_all` 的列表变短，**后续所有索引整体偏移**，于是删错节点、连带删掉别人的内容。

实测代价：一次批量合并后整页差异 0.31%、最大通道差 182，页面结构被破坏。

```python
# ✅ 正确
dead_element.decompose()   # 用收集阶段保存的元素引用
```

## 2. class 不是全页唯一时，不能改/删规则

产物里 `prop-4`、`img-23` 这类类名会在页面出现多次。CSS 是全局的：

- 删一条 `.prop-4 { ... }` 会同时影响 4 个元素；
- 改一条规则会把 4 个元素一起改掉。

处理方式：先统计每个 class 的出现次数，只有 `== 1` 的才允许改/删；否则新增更具体的选择器（如 `.section-bg-3 > .prop-4`）或直接跳过。

实测：加上唯一性检查后，可合并候选从 66 个降到 12 个——大部分"收益"是假的。

## 3. `max_delta = 1` 是正常的，不要追 0

PIL 把多层 PNG 拍平，与浏览器分别渲染再叠加，在 8bit 量化上必然有舍入差：单通道 ±1。

- `max_delta ≤ 1` 且变化像素占比 < 1% → 肉眼不可见，可接受；
- `max_delta ≥ 2` → 通常是半透明叠加，换任何方法都难以完全一致，**放弃这一块**。

实测：`slogan-bg` 合并后 88 个像素变化、maxΔ=1；`title-sub-2/3/4/6` 是 maxΔ=2，全部回滚。

## 4. 删除含子元素的层会丢内容

`decompose()` 会连带删除整棵子树。合并前必须确认目标层是**叶子**（`find("div") is None`），否则跳过。

## 5. `background-size` 存在时不能拍平

带缩放的背景图拍平会引入重采样误差，且不同浏览器插值策略不同。直接跳过。

## 6. 容器固定高度 + flex 会溢出

PSD 容器高度是像素锁定值。子元素改成流式后，累计高度可能超过容器，导致内容压住后续区块。

处理：容器加 `overflow: hidden`，或把容器高度改成 `min-height`（后者会推高后续元素，风险更大）。

## 7. 页面高度变化会让校验直接判失败

`verify_page.py` 在两张截图尺寸不同时直接返回失败。改布局时务必保证页面总高不变——这通常意味着容器高度不能改成 `auto`。

## 8. 层叠顺序：合并后 z-index 取最大值

多个层合成一张后，承载层的 `z-index` 应当取参与合并的层中的**最大值**，否则可能被原本被它压在下面的元素盖住。

## 9. 不要只改 CSS 不改 DOM

删掉 DOM 节点但不删 CSS 规则 → 残留垃圾规则；只删 CSS 不删 DOM → 元素失去样式、位置错乱。两者必须同步。

## 10. 1920 宽设计稿的缩放容器

产物里有 `#canvas-wrap` + `#canvas` 的缩放结构（`transform-origin: top left`）。改布局时不要动这两个容器，否则整页缩放失效、左侧出现空白。

## 11. 文本层不要碰

文本的 `line-height` 被刻意设成 bbox 高度、并加了 `overflow: hidden`，是为了在多字体环境下不溢出。改布局时若给文本层套 flex，可能破坏这两个约束，导致文字被裁。

## 12. 一次只改一块

批量改 20 块再验证，失败时无法定位。实测逐块验证 12 个候选组只需 25 秒，完全承受得起。
