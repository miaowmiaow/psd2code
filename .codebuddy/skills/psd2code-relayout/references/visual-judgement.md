# 从截图设计骨架的准则

结构判断**只看截图**。`assets.json` 用来量间距、找素材、核对坐标，但不用来决定"该怎么排"。

## 判断顺序

1. **扫一遍全页切片**，标出重复出现的单元——重复就是模板，模板就该用 grid / flex 表达。
2. **对每个重复区，找对齐线**：左边缘是否共线？行高是否一致？间距是否等距？
3. **量参数**：用 `assets.json` 里同类元素的 bbox 验证（列 x、行 y、间距）。
4. **写骨架**：容器类型 + 子项顺序 + 间距，落到 `layout.json`。

## 结构识别对照表

| 截图特征 | 判定 |
|---|---|
| 元素沿一个方向等距出现，交叉轴对齐 | `row` / `column` |
| 二维等宽重复（格子墙、卡片墙、表情列表） | `grid`，记录列数与列宽 |
| 子元素纵向叠放且每项内部再分几段 | `column` 套 `cell` |
| 某个元素压在其它元素之上（贴纸、角标、光效） | `absolute` |
| 元素越过父容器边界 | `absolute` |
| 元素带明显旋转 | `absolute` |
| 大面积铺底、其它元素都在它上面 | `background` |

## 间距怎么取

不要凭感觉。同一组内取相邻元素 bbox 的差值，然后**取众数**：

```
列 x 起点：47 / 222 / 398  → 间距 175 / 176 → 取 175
行 y 起点：792 / 999 / 1206 / 1413 → 间距 207 → 取 207
列宽：135（由格子宽度确定）
```

如果间距不一致（174 / 176 / 181），那是设计师手摆的抖动，取众数后统一——这正是"按前端规范重新布局"要修的东西。

## 必须保留的"不规整"

重排不是把所有东西都拉直。下面这些是设计意图，不是错误：

- **刻意的错位**：贴纸斜压、图标半出框、文字与图形的手工相对位置；
- **重叠层级**：角标必须压在图上，光效必须在文字上层；
- **出血**：某些装饰故意越过卡片边界。

判断方法：**如果拉直后视觉明显变了，就保留 `absolute`**。拉直只针对"重复单元的排列"。

## 素材归属怎么定

对每个 slot，在 `assets.json` 里筛 `bbox` 中心落在该单元范围内的素材：

```python
inside = [a for a in assets if center_in(a["bbox"], cell_bbox)]
```

然后按素材在单元内的相对位置归槽位：

- 上部大图 → `icon`
- 中部小条 → `count` / `tag`
- 下部条状 → `label`
- 文本素材直接按 `texts[].text` 匹配语义

找不到合适素材时，说明该槽位是纯色块或纯文字，直接用 CSS 画，不要硬凑图。

## 文案与图片的分工

| 情况 | 处理 |
|---|---|
| `assets.json` 的 `texts[]` 里有该文本 | 用 DOM 文本，套原样式 |
| 文本被渲染成图片（在设计稿里就是图） | 保持图片，不 OCR |
| 数字/计数类（`15x 10`、`10x 奖励:`） | 用 DOM 文本，方便后续改成动态数据 |

最后一条很重要：如果一个"数字"是图片，运营改数据就得重新出图；能识别成文本的应转成文本。

## 置信度与推进顺序

| 置信度 | 情形 | 建议 |
|---|---|---|
| 高 | 规整网格、明确列表 | 直接做 |
| 中 | 大体重复但个别单元特殊（如宝箱列） | 特殊单元单独列一列，其余走 grid |
| 低 | 元素关系靠猜测 | 先保留原结构，或只做最小一块验证 |

## 反例（实测）

南瓜大作战的 `组 8`：3 个子层 bbox 高度重叠，看起来像"一个可合并的图标"。但看图会看出这是 **小图标 + 数字角标**，而数字是**会变化的运营内容**。

判断：角标保留为独立元素（最好是 DOM 文本），不要拍平成一张图。这类判断只能靠看图，`bbox` 重叠率算不出来。
