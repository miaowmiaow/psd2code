# psd2code 产物重排（截图定骨架）

## 铁律

1. **第一步永远是整页截图 → 整页骨架。** 不分区块截图、不扫 DOM 定结构。
2. **骨架定完先校验 `position` 占比**，不达标不进入资源填充。
3. **资源只搬产物里的原始文件**（`images/*.png`、`<span>` 文本），不截新图。
4. **只有一种情况合成图片**：新结构某个位置只需要一张图，而产物那里是多层叠图。
5. **文字永远是 DOM 文本**，不转图。
6. **现阶段不写批量转换脚本。** 一旦写脚本去"快速处理"，就说明在用规则替代视觉判断，必然偏离目标。

## 为什么不能从 DOM 出发

产物的容器边界是设计师随手画的，不代表版面结构：

- `rounded` 一个容器里混着 13 个互不相关的东西；
- `group-col` 里塞了 7 个不同区块；
- 同名 class 结构各异（`prop-bg-2-2` ~ `prop-bg-2-18`）；
- 纯装饰拆成 3 层嵌套。

从这些边界出发写转换器，排出来的一定是「设计师的图层」，不是「页面的版面」。

## 三步法

### 第一步：整页截图 → 整页骨架

**输入**：一张整页截图（宽 = 设计稿宽，高 = 全页）。看的时候整页一起看，因为区块之间的关系（间距、对齐、层级）只在整页里成立。

**输出**：整页结构树，从上往下一行行写。每个节点标注类型与关键判断：

```
page
├ header          column，间距 8，左对齐
│  ├ avatar-row   row，间距 12，垂直居中
│  └ stats        column，间距 6
├ prop-wall       grid，4 列，列宽 142/142/142/139，列距 33/34/33
│  └ card         column，居中
└ task-list       column，间距 16
   └ task-row     row，主轴 space-between
```

写法要求：

- **只写结构**：容器类型、方向、列数、间距、对齐方式；
- **不写坐标**（`top: 792px` 这类属于旧世界）；
- **装饰单独标记**：贴纸、光效、角标这类「压在别的东西上」的元素，标 `decor`，它们在骨架里不占流的位置；
- **同一类单元只写一次**，标注复用次数（`card × 20`）。

判断依据全部来自截图：

| 截图上的样子 | 骨架判定 |
|---|---|
| 元素沿一个方向等距出现、交叉轴对齐 | `row` / `column` |
| 二维等宽重复 | `grid`，记列数与列宽 |
| 某个元素压在别的东西上 | `decor`，脱离流 |
| 大面积铺底 | 容器的 `background`，不占子项 |
| 元素越出容器边界 | 需确认：是装饰出血，还是容器画小了 |

### 第二步：校验 position 占比

骨架落成 CSS 后，统计：

```
position: absolute 的规则数 / CSS 规则总数
```

- **目标 < 10%**；
- 超过 10%，说明骨架里还在用坐标摆东西，回第一步重写；
- 达标但视觉崩了，说明骨架本身的层级判断错了（容器边界认错、方向判反、间距归一化），同样回第一步。

两个指标都要看：**`position` 占比达标 ≠ 骨架正确**。指标只证明「没有用绝对定位」，不证明「结构合理」。

### 第三步：资源填充

按骨架的槽位，逐个去产物里找资源：

| 槽位情况 | 处理 |
|---|---|
| 产物在这里是**单层**图片 | 直接引用原文件，不改 |
| 产物在这里是**多层叠图**（如 4 层叠成的图标） | 合成一张（按 DOM 文档顺序叠加，不是 z-index） |
| 产物在这里是**文本** | 取 `<span>` 的原始文本 |
| 找不到对应资源 | 说明该槽位是纯色/纯文字，用 CSS 画，不要硬凑图 |

合成与复用的硬规则：

- **合成只发生在单个槽位内部**，不跨槽位合并；
- 合成结果**按内容 hash 去重**（20 个格子通常只有 4~5 种图形）；
- 合成图**必须是透明底**，不能把父容器的底色烘进图片；
- **模板 + 数据**：同构单元共用一套 class，差异走内联 CSS 变量或 data 属性，不要复制 N 份结构。

## 反模式

| 反模式 | 为什么错 |
|---|---|
| 写 `flexify.py` 这类通用转换器 | 版面结构没有共性，写不出通用算法；跑出来 position 0%、页面报废 |
| 从 DOM 容器边界推骨架 | 继承的是设计师的图层分组，不是版面 |
| 用坐标统计猜方向/间距 | x/y 谁 spread 大不代表语义；间距归一会逐级累积误差 |
| 分区块截图定结构 | 丢掉区块之间的间距与对齐关系 |
| 追求 `position` 指标而牺牲视觉 | 指标完美 ≠ 结构合理 |
| 把整格/整块截成图片 | 背景被固化、素材不可复用、有状态的控件被烧死 |
| 用规则脚本"快速处理"多块 | 脚本能给出数字，给不出判断 |

## 交付前的自检

- [ ] 骨架是从**整页截图**写出来的，不是从 DOM 反推的
- [ ] `position` 占比 < 10%
- [ ] 视觉与截图对比过，区块顺序、列数、对齐方式一致
- [ ] 图片引用的是产物里的原始文件；合成图有透明通道、已去重
- [ ] 文字全部是 DOM 文本
- [ ] 同构单元是模板 + 数据，不是复制粘贴
